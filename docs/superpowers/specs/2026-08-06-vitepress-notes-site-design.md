# VitePress 在线笔记站设计

## 1. 背景与目标

当前仓库包含三组学习笔记：

- `python/`：14 篇 Python 笔记及配套图片；
- `LangChain_1.2/`：10 篇 LangChain 笔记及配套图片；
- `LangGraph/`：6 篇 LangGraph 笔记、配套图片，以及一个独立的运行时可视化页面。

项目将在不批量改写原始 Markdown、不破坏现有相对图片路径的前提下，建设为可长期维护的中文 VitePress 文档网站。网站需要支持本地搜索、深浅色模式、多级目录、文章大纲、上一篇/下一篇、Mermaid、KaTeX 数学公式、响应式布局和 GitHub Pages 自动部署。

## 2. 设计原则

1. **内容原地接入**：保留现有三组笔记目录，不为追求模板结构而迁移内容。
2. **内容优先**：首页和文章页服务于查找与阅读，不采用营销落地页式的信息密度和动效。
3. **低维护成本**：新增笔记后，通过生成脚本自动更新侧边栏，不要求逐篇维护配置。
4. **渐进增强**：无 Frontmatter 的文档可正常工作；Frontmatter 只用于可选覆盖。
5. **单一配置源**：站点名称、副标题、GitHub 地址和部署基础路径集中定义。
6. **最小内容修改**：只有在构建或链接验证确实失败时，才对原始笔记做局部修复。

## 3. 方案选择

### 采用方案：仓库根目录作为内容根

VitePress 直接以仓库根目录为内容根，并新增根级 `index.md`、`about.md`、`.vitepress/`、`scripts/` 和部署工作流。侧边栏脚本只扫描明确允许的内容目录，不扫描项目配置和设计文档。

该方案的优势：

- 现有 Markdown 和图片不移动，相对引用保持不变；
- Git 历史连续，差异集中在站点基础设施；
- 后续笔记仍可按当前目录习惯维护；
- 与参考站点的内容组织方式相近，但实现、视觉和品牌均独立。

未采用的方案：

- 将笔记迁移到 `docs/notes/`：会产生大量路径变更，收益不足以抵消迁移风险；
- 在 `docs/` 下生成代理页或使用软链接：会增加构建、路由和相对资源解析复杂度。

## 4. 信息架构与路由

### 4.1 顶部导航

- 首页：`/`
- 笔记：进入统一笔记导览页 `/notes`
- 关于：`/about`
- GitHub：指向 `https://github.com/wang844314728/My-study-materials`

GitHub 地址与站点文案统一放在配置模块中，主题和首页复用该配置。统一笔记导览页列出三个分类、章节数量和各分类的起始入口。

### 4.2 内容分类

- Python：`/python/`
- LangChain 1.2：`/LangChain_1.2/`
- LangGraph：`/LangGraph/`

为每个分类生成或维护一个轻量目录首页，展示章节列表和简短说明。原始章节文件保持原名和原路径。

### 4.3 文章导航

- 左侧：按分类和文件顺序展示章节；目录结构扩展后支持递归分组；
- 右侧：展示当前文章二级及更深标题；
- 底部：使用稳定排序生成上一篇、下一篇；
- 移动端：使用 VitePress 抽屉式导航和搜索入口。

### 4.4 LangGraph 运行时可视化

`LangGraph/langgraph-runtime-viz/` 作为站内静态交互页面发布，不改写其核心交互逻辑。构建流程将它复制到站点公共目录的稳定路径，并在 LangGraph 分类首页及相关笔记中提供入口。该页面需要在 GitHub Pages 子路径下也能加载自身资源。

## 5. 侧边栏生成

新增 `scripts/generate-sidebar.mjs`，扫描允许列表中的 `python/`、`LangChain_1.2/`、`LangGraph/`。

生成规则：

1. 忽略隐藏文件、`assets`、`.git`、`.vitepress`、`node_modules`、`dist`、独立可视化目录及非 Markdown 文件；
2. 递归读取目录，按层级生成分组；
3. `index.md` 作为目录首页，并排在同级其他文章之前；
4. 标题优先级为 Frontmatter `title`、首个一级标题、格式化后的文件名；
5. 排序优先级为显式 Frontmatter `order`、文件名数字前缀、文件名自然排序；
6. 路由由相对文件路径生成，保留 Unicode 路径并使用规范化的 URL 分隔符；
7. 输出 TypeScript 数据文件到 `.vitepress/sidebar.ts`；
8. 输出稳定排序，避免相同输入产生无意义差异。

脚本采用 Node.js 标准库实现。Frontmatter 只解析本任务需要的简单顶层字段，不为此额外引入完整 YAML 依赖；若后续需要复杂 YAML，可再引入专用解析器。

开发和构建命令都会先运行生成脚本。生成结果提交进 Git，便于审阅和排查。

## 6. Markdown 与主题增强

### 6.1 基础 Markdown

沿用 VitePress 默认 Markdown 能力，包括代码语法高亮、复制按钮、代码行高亮、任务列表、引用、表格和标题锚点。代码行号通过全局配置启用或允许页面按需控制。

### 6.2 Mermaid

使用 Mermaid 客户端渲染 `mermaid` 围栏代码块。渲染逻辑只在浏览器运行，避免静态构建访问 DOM。主题监听 VitePress 的深浅色状态：浅色使用中性主题，深色使用 dark 主题；切换主题时重新渲染对应图表。

Mermaid 失败时保留可读的错误状态和原始代码，不让单个图表影响整页。

### 6.3 数学公式

使用 KaTeX 及对应 Markdown-it 插件解析行内 `$...$` 和块级 `$$...$$`，并在主题入口加载 KaTeX 样式。公式溢出时允许横向滚动，避免撑破移动端页面。

### 6.4 图片与表格

- 正文图片限制最大宽度为容器宽度，高度自动；
- 普通图片块自然居中，保留替代文本；
- 宽表格外层允许横向滚动；
- 单元格不强制压缩到不可读宽度；
- 图片加载失败不改变正文整体布局。

### 6.5 搜索

启用 VitePress 内置本地搜索，并配置中文界面文案。搜索索引在构建阶段生成，不依赖外部服务。结果展示页面标题、章节标题和命中上下文。

## 7. 视觉方向

视觉采用“技术手册与个人批注本”的编辑化方向，而不是通用 AI 产品模板。

具体约束：

- 使用系统中文字体栈，不引入远程或商业字体；
- 主体以近白纸张色和深墨色为基础，使用单一低饱和强调色；
- 首页首屏保持紧凑，不使用超大口号、人物插画或装饰性三维图形；
- 分类卡片以编号、课程名称、章节数量和真实章节标题构成，不堆叠空泛卖点；
- 不使用大面积渐变、玻璃拟态、发光阴影、彩色光斑、无意义网格背景；
- 不滥用胶囊按钮、Sparkles 图标、浮动卡片或循环动画；
- 圆角和阴影只用于建立层级，数值统一且克制；
- 正文宽度适合中文长文阅读，标题、段落、列表和代码块形成稳定节奏；
- 深色模式不是简单反色，分别调整正文、边框、代码块、表格和 Mermaid 对比度；
- 动效只保留必要的交互反馈，并遵守 `prefers-reduced-motion`。

首页内容：

1. 站点名称 `Yook's Notes`；
2. 副标题“记录学习、研究与思考”；
3. “开始阅读”和“查看 GitHub”两个操作；
4. Python、LangChain、LangGraph 三张分类卡片；
5. 最近更新或推荐阅读，内容由真实笔记生成；
6. 搜索、结构化阅读、持续维护三项简短说明。

## 8. 配置与依赖

### 8.1 运行环境

- Node.js 20 或更高版本；
- npm；
- VitePress；
- TypeScript 配置文件。

### 8.2 依赖原则

只保留以下职责明确的运行依赖：

- `vitepress`：静态文档框架、主题、本地搜索和构建；
- `mermaid`：流程图渲染；集成层由项目主题实现，不再引入 Mermaid 封装插件；
- `katex` 与 `@mdit/plugin-katex`：数学公式解析和样式。

每项最终依赖都在 README 中说明用途。

### 8.3 npm 命令

- `docs:generate`：生成侧边栏和必要的衍生内容；
- `docs:dev`：生成后启动开发服务器；
- `docs:build`：生成后执行生产构建；
- `docs:preview`：预览生产构建；
- 可增加只读的链接或内容校验命令，但不改变上述命令语义。

## 9. GitHub Pages 部署

新增 `.github/workflows/deploy.yml`：

1. 推送到默认分支和手动触发时运行；
2. 使用 Node.js 20；
3. 使用 `npm ci` 安装 lockfile 中的依赖；
4. 设置 Pages 所需的最小权限和并发策略；
5. 通过官方 Pages configure、artifact upload 和 deploy Actions 发布构建目录；
6. 工作流通过 `VITEPRESS_BASE` 向构建注入唯一基础路径配置。

本仓库是普通项目仓库，因此工作流默认使用 `/My-study-materials/`。本地开发默认使用 `/`。README 同时说明用户名主页仓库和普通项目仓库的配置方式，不在多个文件中重复硬编码仓库名。

## 10. 错误处理与内容保护

- 侧边栏生成遇到无法解析的文档时，报告文件路径并以文件名回退，而不是修改原文；
- 路由冲突、重复条目或缺失扫描目录会使生成命令失败，并给出明确错误；
- 构建前验证本地图片引用，缺失资源报告来源文件和引用路径；
- 外部链接不作为生产构建的硬失败条件；
- Mermaid 和公式的单项渲染错误在页面内隔离；
- 原始笔记若存在 VitePress 不兼容语法，只做可解释、可审阅的最小修复。

## 11. 验证策略

### 11.1 自动验证

- 侧边栏生成器的关键规则测试：标题优先级、排序、`index.md`、Unicode 路径、忽略规则；
- 本地图片引用完整性检查；
- `npm install` 生成或更新 lockfile；
- `npm run docs:build` 必须成功；
- 检查构建产物包含首页、三类笔记、关于页和交互页面；
- 检查生成 HTML 中的基础路径和主要内部链接。

### 11.2 浏览器验证

本地启动网站，验证：

- 首页、分类页和至少每类一篇文章可打开；
- 左侧目录、右侧大纲、上一篇/下一篇可用；
- 中文搜索在桌面端和移动端可操作；
- Mermaid 和数学公式正常渲染；
- 图片、宽表格和代码块不产生明显横向溢出；
- 深浅色切换后的正文和图表可读；
- LangGraph 运行时可视化可在站内打开和交互；
- GitHub Pages 项目子路径下的资源链接正确。

## 12. 交付范围

主要新增或修改：

- 根级首页、统一笔记导览页、关于页与分类首页；
- `.vitepress/config.mts`、侧边栏数据和自定义主题；
- 侧边栏与内容校验脚本；
- Mermaid 和 KaTeX 集成；
- LangGraph 可视化页面的站内发布接入；
- `package.json`、`package-lock.json`、`.gitignore`；
- GitHub Pages 工作流；
- 中文 README；
- 必要且最小的 Markdown 兼容性修复。

不包含：评论系统、用户账户、服务端搜索、分析追踪、CMS、离线 PWA 或内容批量重写。

## 13. 完成标准

满足以下条件才可宣布完成：

1. 所有 30 篇现有笔记均能通过站点目录访问；
2. 当前 401 处本地笔记图片引用均有效；
3. 三个分类、首页、关于页和交互页面均出现在构建产物中；
4. 搜索、Mermaid、KaTeX、深浅色和文章导航已配置并实际验证；
5. `npm run docs:build` 成功；
6. GitHub Pages 工作流、基础路径和 README 说明相互一致；
7. 原始笔记内容未被无关改写。
